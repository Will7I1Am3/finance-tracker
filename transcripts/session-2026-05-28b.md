**Assistant:** That's a Vite environment variable configuration for local development.

`VITE_API_URL=http://localhost:8000` tells the frontend where to find the backend API when running locally. Without it, the frontend wouldn't know what URL to send API requests to.

Vite exposes any variable prefixed with `VITE_` to your frontend code via `import.meta.env.VITE_API_URL`. Your `client.js` almost certainly uses that to build the base URL for all fetch calls — so instead of hardcoding `http://localhost:8000`, it reads that env var.

In production on Railway, `VITE_API_URL` is set to the actual backend subdomain at build time instead.

**Assistant:** That's the bug — when you cancel Google's login, Google sends `?error=access_denied` back to the callback, and your code tries to exchange that for a token instead of handling it gracefully, causing a 500. Let me see the callback.

*(Read `backend/routers/auth.py`)*

Easy fix — just check for `error` in the query params at the top of the callback and redirect back to the frontend login instead of crashing.

```python
@router.get("/callback")
async def callback(request: Request):
    if request.query_params.get("error"):
        return RedirectResponse(url=_FRONTEND)

    token = await oauth.google.authorize_access_token(request)
```

Now if you cancel on Google's login page, the callback detects `error=access_denied` and redirects you back to the frontend (which will show the Login page) instead of throwing a 500.
