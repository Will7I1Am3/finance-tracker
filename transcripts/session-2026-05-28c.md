All code is production-ready. Missing only Railway configuration files and manual dashboard steps. Created `backend/railway.toml` and `frontend/railway.toml`, then provided the following 8-step deployment guide:

**Step 1 — Push code to GitHub**
```bash
git add backend/railway.toml frontend/railway.toml
git commit -m "Add Railway deployment config"
git push
```

**Step 2 — Create a Railway account**
Go to railway.app and sign up (use GitHub login). Click New Project.

**Step 3 — Create the Backend service**
Add Service → GitHub Repo → select repo. In Settings, set Root Directory to `backend`. Railway reads `backend/railway.toml` automatically.

**Step 4 — Create the Frontend service**
New → GitHub Repo (same repo, second service). In Settings, set Root Directory to `frontend`. Railway reads `frontend/railway.toml`.

**Step 5 — Note your Railway domains**
Go to each service → Settings → Networking → Generate Domain. Write both down.

**Step 6 — Set environment variables**

Backend service:
| Variable | Value |
|---|---|
| `ANTHROPIC_API_KEY` | your Anthropic key |
| `GOOGLE_CLIENT_ID` | from Google Cloud Console |
| `GOOGLE_CLIENT_SECRET` | from Google Cloud Console |
| `COOKIE_SECRET` | `python -c "import secrets; print(secrets.token_hex(32))"` |
| `DATABASE_URL` | Supabase pooler URL |
| `FRONTEND_URL` | `https://your-frontend.up.railway.app` |
| `BACKEND_URL` | `https://your-backend.up.railway.app` |
| `DAILY_UPLOAD_LIMIT` | `10` |
| `ENVIRONMENT` | `production` |

Frontend service:
| Variable | Value |
|---|---|
| `VITE_API_URL` | `https://your-backend.up.railway.app` |

**Step 7 — Update Google Cloud Console**
APIs & Services → Credentials → your OAuth client → add `https://your-backend.up.railway.app/auth/callback` to Authorized Redirect URIs. Keep `http://localhost:8000/auth/callback` for local dev.

**Step 8 — Smoke test**
Visit frontend URL, sign in with Google, upload a PDF, confirm save, check Supabase for rows, try duplicate upload (expect 409).

**Assistant:** Recommended Vercel for the frontend. Key points:

**Vercel (recommended for frontend)**
- Purpose-built for React/Vite static sites — zero config
- Free tier, global CDN, fast builds
- Only needs one env var (`VITE_API_URL`)

**Railway for frontend**
- Everything in one dashboard (minor convenience)
- But runs a Node.js process just to serve static files — wasteful, costs compute credits
- Needs the `serve` workaround

The backend already handles cross-origin correctly (`SameSite=None; Secure=True` when `ENVIRONMENT=production`, CORS driven by `FRONTEND_URL`), so a Vercel URL works fine.

Suggested: Railway for backend only (1 service), Vercel for frontend.

**User:** I also heard people talk about Render. What is that?

---

**Assistant:** Explained Render as another cloud hosting platform. Comparison:

| | Railway | Render | Vercel |
|---|---|---|---|
| **Best for** | Backend services | Backend services | Frontend/static sites |
| **Free tier** | $5 credit/month, then pay-as-you-go | Free tier (spins down after inactivity) | Generous free tier |
| **Cold starts** | No (always on on paid) | Yes on free tier — sleeps after 15 min, ~30s wake-up | N/A (static) |
| **DX / setup** | Very easy | Easy | Easiest for frontend |
| **Static sites** | Works but awkward | Supported natively | Purpose-built for it |

Recommendation: Railway (backend) + Vercel (frontend) as the most common pairing for this type of project.

**Assistant:** Yes, effectively. Railway gives a one-time $5 trial credit on signup, but after that you need the Hobby plan at $5/month. The free tier is basically just the trial.

- **Render free tier** — works, but 30s cold start. Can warm it up by opening the backend URL a minute before demoing.

**Paid:**
- **Railway $5/month** — best experience

**Honest take for a class project:** Render free + Vercel = $0 total. Cold start is manageable for demos. If you want always-on, Railway at $5/month is worth it.
